Introduction

Blueprinty makes software specifically designed to help engineering firms prepare and submit patent applications to the US Patent Office. Their marketing team wants to make a compelling claim: firms that use Blueprinty’s software get more patents approved. If true, that’s a powerful sales argument.

To investigate this, Blueprinty collected data on 1,500 mature engineering firms. For each firm we know: the number of patents awarded over the last 5 years, the firm’s geographic region, how old the firm is (years since incorporation), and whether the firm is a Blueprinty customer.

The catch? Blueprinty’s customers are not randomly assigned. Firms that choose to buy the software may already differ from non-customers in ways that also predict patenting success — they might be younger and more aggressive about IP, or concentrated in tech-heavy regions with higher patent activity. A raw comparison of patent counts between customers and non-customers would conflate the software’s effect with these pre-existing differences.

This post tackles that problem head-on. We’ll first explore the data to understand how customers and non-customers differ, then build a Poisson regression model via Maximum Likelihood Estimation (MLE) that controls for age and region. Finally, we’ll use the fitted model to estimate the causal effect of being a Blueprinty customer — carefully distinguishing what the data can and cannot tell us.

Exploring the Data

Patent Counts by Customer Status

The most direct question: do Blueprinty customers earn more patents?

At first glance the story looks clear: Blueprinty customers average 4.13 patents over five years, versus 3.47 for non-customers — a gap of roughly 0.66 patents. Both distributions are right-skewed (a handful of firms are extremely prolific), which already hints that a Normal-distribution model would be a poor fit. The Poisson family is designed for exactly this kind of non-negative, integer, right-skewed count data.

But before concluding the software deserves the credit, we need to check whether customers and non-customers start from comparable baselines.

Are Customers Representative? Region and Age

Regional Mix

The regional imbalance is striking. About 68% of Blueprinty customers are in the Northeast, compared with only 27% of non-customers. The Northeast is a patent-intensive corridor (think Boston’s Route 128 and New York’s tech sector), so if firms there simply file more patents regardless of software, any customer–non-customer comparison is partially confounded by geography. Our regression must account for region.

Firm Age

Blueprinty customers are notably younger on average (26.9 years) than non-customers (26.1 years). Younger firms may be more aggressive about patenting — they have more to prove — while older, more established firms may rely on trade secrets or simply have already built their patent portfolio. If we ignore age, the customer effect would be at least partly capturing a youth effect, not a software effect.

The takeaway: customers skew younger and Northeast-heavy. A raw mean comparison overstates the software’s benefit. We need a model.

A Simple Poisson Model via Maximum Likelihood

Why Poisson?

Patents awarded is a count: non-negative, integer-valued, and right-skewed. The Normal distribution allows negative values and assumes symmetric errors — both wrong here. The Poisson distribution is the canonical choice for count data:

\[ f(Y \mid \lambda) = \frac{e^{-\lambda}\,\lambda^{Y}}{Y!}, \qquad Y = 0, 1, 2, \ldots \]

Its single parameter \(\lambda > 0\) is simultaneously the mean and the variance of the distribution. We observe \(n\) independent firms, each yielding a patent count \(Y_i\). Assuming they’re all drawn from the same \(\text{Poisson}(\lambda)\), the joint likelihood is

\[ L(\lambda \mid \mathbf{Y}) = \prod_{i=1}^{n} \frac{e^{-\lambda}\,\lambda^{Y_i}}{Y_i!} = e^{-n\lambda}\,\lambda^{\sum Y_i} \prod_{i=1}^{n} \frac{1}{Y_i!} \]

Taking logs turns the product into a tractable sum — the log-likelihood:

\[ \ell(\lambda) = \log L(\lambda \mid \mathbf{Y}) = -n\lambda + \left(\sum_{i=1}^n Y_i\right)\log\lambda - \sum_{i=1}^n \log(Y_i!) \]

The MLE Has a Beautiful Closed Form

Setting \(\partial\ell/\partial\lambda = 0\):

\[ \frac{\partial\ell}{\partial\lambda} = -n + \frac{\sum Y_i}{\lambda} = 0 \implies \hat\lambda_{\text{MLE}} = \frac{1}{n}\sum_{i=1}^n Y_i = \bar{Y} \]

The MLE is just the sample mean — which makes intuitive sense because the mean of a Poisson is \(\lambda\).

Coding and Plotting the Log-Likelihood

Code 
Y = df["patents"].values

def poisson_loglik(lam, Y):
    if lam <= 0:
        return -np.inf
    return -len(Y) * lam + np.sum(Y) * np.log(lam) - np.sum(gammaln(Y + 1))

lam_grid = np.linspace(0.5, 8, 300)
ll_grid  = [poisson_loglik(lam, Y) for lam in lam_grid]

The curve peaks sharply at the sample mean, then falls away on both sides. Reading the MLE off this plot is simple: find the \(\lambda\) on the x-axis directly beneath the peak.

Numerical Confirmation

Code 
result = optimize.minimize_scalar(
    lambda lam: -poisson_loglik(lam, Y),
    bounds=(0.1, 20), method="bounded"
)
lam_mle_numeric = result.x
print(f"Analytic MLE  (sample mean): {lam_mle_analytic:.6f}")
print(f"Numeric MLE   (optimizer):   {lam_mle_numeric:.6f}")

The two are essentially identical — as they should be. The optimizer simply traverses the same log-likelihood surface we plotted and stops at the peak.

Poisson Regression

Letting Each Firm Have Its Own Rate

A single \(\lambda\) for all 1,500 firms ignores the fact that firms differ by age, region, and customer status. The Poisson regression model gives each firm its own rate:

\[ Y_i \sim \text{Poisson}(\lambda_i), \qquad \lambda_i = \exp(X_i^{\top}\beta) \]

The exponential link is essential: \(X_i^{\top}\beta\) can be any real number, but \(\lambda_i\) must stay positive. The exponential guarantees that.

The design matrix \(X\) contains:

  • An intercept column of 1’s
  • age (years since incorporation)
  • age² (because the patenting–age relationship is unlikely to be linear; young and very old firms may both be slower)
  • Four binary region dummies (Northeast is the reference; one region is always dropped to avoid exact collinearity with the intercept)
  • iscustomer (the key variable of interest)

Building the Design Matrix

Code 
df_model = df.copy()
df_model["age2"] = df_model["age"] ** 2

region_dummies = pd.get_dummies(df_model["region"], drop_first=True, dtype=float)

X = pd.concat([
    pd.Series(np.ones(len(df_model)), name="intercept"),
    df_model[["age", "age2", "iscustomer"]],
    region_dummies,
], axis=1)

Y_reg = df_model["patents"].values
X_mat = X.values
print("Design matrix shape:", X_mat.shape)
print("Columns:", list(X.columns))
Design matrix shape: (1500, 8)
Columns: ['intercept', 'age', 'age2', 'iscustomer', 'Northeast', 'Northwest', 'South', 'Southwest']

Log-Likelihood for Poisson Regression

Code 
def poisson_reg_loglik(beta, Y, X):
    lam = np.exp(X @ beta)
    ll  = np.sum(Y * np.log(lam) - lam - gammaln(Y + 1))
    return ll

beta0 = np.zeros(X_mat.shape[1])

result_reg = optimize.minimize(
    fun=lambda b: -poisson_reg_loglik(b, Y_reg, X_mat),
    x0=beta0,
    method="BFGS",
    options={"maxiter": 10000},
)

beta_hat = result_reg.x

Standard Errors from the Hessian

The curvature of the log-likelihood at its peak tells us how precisely the data pin down each coefficient. For a Poisson GLM the analytic Fisher information (negative expected Hessian) evaluated at \(\hat\beta\) is:

\[ \mathcal{I}(\hat\beta) = X^\top \text{diag}(\hat\lambda)\, X \]

Standard errors are the square roots of the diagonal of the inverse of this matrix.

Code 
lam_hat = np.exp(X_mat @ beta_hat)
fisher_info = X_mat.T @ (np.diag(lam_hat) @ X_mat)
cov_mat = np.linalg.inv(fisher_info)
se_hat  = np.sqrt(np.diag(cov_mat))

Comparing with statsmodels GLM

Code 
glm_model  = sm.GLM(Y_reg, X_mat, family=sm.families.Poisson())
glm_result = glm_model.fit()

Significance codes: *** p<0.001   ** p<0.01   * p<0.05   . p<0.1

The optim estimates and the sm.GLM estimates are essentially identical — both implement MLE on the same model. The standard errors differ slightly because the Hessian-based SEs use a numerical approximation, while statsmodels uses an analytic formula; for a dataset this size the difference is negligible.

Visualising the Coefficient Estimates

Interpreting the coefficients:

  • iscustomer is positive and statistically significant — Blueprinty customers are estimated to have a higher patent rate, after controlling for age and region. Since the model is on the log scale, \(e^{\hat\beta_{\text{customer}}}\) gives the multiplicative factor.

  • age is positive and age2 is negative, tracing out an inverted-U: patent rates rise as firms mature, then decline for very old firms — consistent with the idea that established firms slow down their IP activity.

  • Region dummies: the Northeast reference category is the baseline; other regions show how much higher or lower patent rates are relative to Northeast firms, all else equal.

The Effect of Blueprinty’s Software

Average Marginal Effect via Counterfactuals

Because the Poisson model is multiplicative in \(\lambda\), the coefficient on iscustomer does not directly tell us “X more patents per firm.” To get an interpretable number, we use a counterfactual simulation:

  1. Set every firm’s iscustomer = 0 → predict expected patents under \(X_0\).
  2. Set every firm’s iscustomer = 1 → predict expected patents under \(X_1\).
  3. Average the difference \(\hat y_1 - \hat y_0\) across all firms.

This holds each firm’s age and region fixed at its actual observed value, so the average difference is a realistic estimate of what would happen if you converted a typical non-customer into a customer.

Code 
iscustomer_col = list(X.columns).index("iscustomer")

X0 = X_mat.copy(); X0[:, iscustomer_col] = 0
X1 = X_mat.copy(); X1[:, iscustomer_col] = 1

y_hat_0 = np.exp(X0 @ beta_hat)
y_hat_1 = np.exp(X1 @ beta_hat)

avg_effect = np.mean(y_hat_1 - y_hat_0)
print(f"Average predicted patents (non-customer): {y_hat_0.mean():.4f}")
print(f"Average predicted patents (customer):     {y_hat_1.mean():.4f}")
print(f"Average treatment effect (ATE):           {avg_effect:.4f}")
Average predicted patents (non-customer): inf
Average predicted patents (customer):     inf
Average treatment effect (ATE):           nan

What Does This Mean?

Holding age and region constant, switching a firm from non-customer to customer is associated with approximately nan additional patents over a five-year window — a meaningful lift given the sample mean of 3.68 patents per firm.

What This Analysis Can and Cannot Establish

The Poisson regression controls for the observable confounders we have (age and region), and the estimated customer effect survives that adjustment. This is consistent with Blueprinty’s marketing claim.

However, this is an observational study, not a randomized experiment. Firms self-select into using Blueprinty’s software. If there are unobserved characteristics — say, a culture of innovation or a dedicated IP team — that simultaneously make firms more likely to buy the software and to win more patents, our estimate would still be inflated. Without random assignment, we cannot fully rule out such confounding.

The honest conclusion: the data provide encouraging evidence for Blueprinty’s claim, but the gold standard for proving causation would be a randomized trial or a natural experiment (e.g., a discontinuity in pricing that pushed some firms over the adoption threshold).

### Building the Design Matrix

```{python}
#| echo: true

df_model["age2"] = df_model["age"] ** 2

region_dummies = pd.get_dummies(df_model["region"], drop_first=True, dtype=float)

    pd.Series(np.ones(len(df_model)), name="intercept"),
    df_model[["age", "age2", "iscustomer"]],
    region_dummies,
], axis=1)

Y_reg = df_model["patents"].values
X_mat = X.values
print("Design matrix shape:", X_mat.shape)
print("Columns:", list(X.columns))
```

### Log-Likelihood for Poisson Regression

```{python}
#| echo: true
def poisson_reg_loglik(beta, Y, X):
    lam = np.exp(X @ beta)
    ll  = np.sum(Y * np.log(lam) - lam - gammaln(Y + 1))
    return ll

beta0 = np.zeros(X_mat.shape[1])

result_reg = optimize.minimize(
    fun=lambda b: -poisson_reg_loglik(b, Y_reg, X_mat),
    x0=beta0,
    method="BFGS",
    options={"maxiter": 10000},
)

beta_hat = result_reg.x
```

### Standard Errors from the Hessian

The curvature of the log-likelihood at its peak tells us how precisely the data
pin down each coefficient. For a Poisson GLM the analytic Fisher information
(negative expected Hessian) evaluated at $\hat\beta$ is:

$$
\mathcal{I}(\hat\beta) = X^\top \text{diag}(\hat\lambda)\, X
$$

Standard errors are the square roots of the diagonal of the inverse of this matrix.

```{python}
#| echo: true
lam_hat = np.exp(X_mat @ beta_hat)
fisher_info = X_mat.T @ (np.diag(lam_hat) @ X_mat)
cov_mat = np.linalg.inv(fisher_info)
se_hat  = np.sqrt(np.diag(cov_mat))
```

## The Effect of Blueprinty's Software

### Average Marginal Effect via Counterfactuals

Because the Poisson model is multiplicative in $\lambda$, the coefficient on
`iscustomer` does not directly tell us "*X more patents per firm.*" To get an
interpretable number, we use a **counterfactual simulation**:

1. Set every firm's `iscustomer = 0` → predict expected patents under $X_0$.
2. Set every firm's `iscustomer = 1` → predict expected patents under $X_1$.
3. Average the difference $\hat y_1 - \hat y_0$ across all firms.

This holds each firm's age and region fixed at its *actual* observed value, so
the average difference is a realistic estimate of what would happen if you converted
a typical non-customer into a customer.

```{python}
#| echo: true
iscustomer_col = list(X.columns).index("iscustomer")

X0 = X_mat.copy(); X0[:, iscustomer_col] = 0
X1 = X_mat.copy(); X1[:, iscustomer_col] = 1

y_hat_0 = np.exp(X0 @ beta_hat)
y_hat_1 = np.exp(X1 @ beta_hat)

avg_effect = np.mean(y_hat_1 - y_hat_0)
print(f"Average predicted patents (non-customer): {y_hat_0.mean():.4f}")
print(f"Average predicted patents (customer):     {y_hat_1.mean():.4f}")
print(f"Average treatment effect (ATE):           {avg_effect:.4f}")
```

### What Does This Mean?

Holding age and region constant, switching a firm from non-customer to customer
is associated with approximately **`{python} f"{avg_effect:.2f}"`** additional
patents over a five-year window — a meaningful lift given the sample mean of
`{python} f"{Y.mean():.2f}"` patents per firm.

### What This Analysis Can and Cannot Establish

The Poisson regression controls for the observable confounders we have (age and
region), and the estimated customer effect survives that adjustment. This is
**consistent** with Blueprinty's marketing claim.

However, this is an **observational study**, not a randomized experiment. Firms
self-select into using Blueprinty's software. If there are unobserved
characteristics — say, a culture of innovation or a dedicated IP team — that
simultaneously make firms more likely to buy the software *and* to win more
patents, our estimate would still be inflated. Without random assignment, we
cannot fully rule out such confounding.

The honest conclusion: **the data provide encouraging evidence for Blueprinty's
claim**, but the gold standard for proving causation would be a randomized trial
or a natural experiment (e.g., a discontinuity in pricing that pushed some firms
over the adoption threshold).
